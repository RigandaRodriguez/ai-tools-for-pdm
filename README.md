# Кто выгуливает Бориса

Учебный micro-MVP для вымышленной компании «Догяндекс»: общая страница для записи сотрудников на прогулки с офисным псом Борисом.

## Статус

Приложение показывает текущую дату по Москве и пять слотов из SQLite. Доступна запись по синтетическому ФИО: сервер атомарно занимает только свободный слот и отклоняет повторную попытку. Работает карточка последнего кормления с новой отметкой по ФИО. Реализация готова: все семь DoD и итоговый smoke-check проверены 06.11.2026. Итоговый результат принят студентом 06.11.2026. Учебный micro-MVP завершён.

Этапы реализации и проверки интерфейса приняты студентом. Итоговая проверка включала запись на прогулку и конфликт из заранее открытой формы при размерах окна 1440×900 и 375×812, сохранение после обновления и в независимом браузерном сеансе, новую отметку кормления и чтение фактических строк SQLite. Это проверка размеров окна браузера, а не физического мобильного устройства. Исправлений после smoke-check не потребовалось.

Единственный источник продуктовых требований — [spec.md](spec.md). Порядок работы определён в [AGENTS.md](AGENTS.md), этапы и результаты проверок фиксируются в [PLAN.md](PLAN.md). README и PLAN не изменяют требования спецификации.

## Назначение и главный сценарий

Гипотеза: пять понятных слотов на сегодня позволяют сотруднику самостоятельно записаться на прогулку без обращения к администратору.

Главный сценарий:

1. Сотрудник открывает страницу и видит текущую дату и пять слотов: `09:00`, `11:00`, `13:00`, `15:00`, `17:00`.
2. Выбирает свободный слот, вводит синтетическое ФИО и подтверждает запись.
3. Слот становится занятым и показывает введённое ФИО.
4. Повторная попытка занять этот слот отклоняется сервером с понятным сообщением; первоначальная запись сохраняется.
5. После обновления страницы и открытия приложения во втором браузере запись остаётся видна.

После успешной записи показывается подтверждение, занятый слот отображает ФИО и больше не содержит форму. При конфликте страница показывает понятное сообщение и актуальный список слотов. Имя после удаления лишних пробелов должно быть непустым. Форма, открытая до смены даты по Москве, не позволяет записаться на прошлую дату.

Карточка «Последнее кормление» показывает ФИО, дату и время последней отметки по Москве. До первой отметки отображается «Кормлений пока не отмечали». Чтобы отметить кормление, введите синтетическое ФИО в форме карточки и нажмите «Отметить кормление». Сервер сохраняет новую строку в SQLite, а карточка показывает последнюю добавленную отметку. Пустое после обработки пробелов имя отклоняется с понятным сообщением. Обновление страницы после успеха не отправляет отметку повторно.

## Технические требования

- Минимальный локальный проект на установленном Node.js и npm, без новых фреймворков, внешних сервисов и инфраструктуры.
- Настоящий SQLite-файл в папке проекта. Таблицы `walk_slots` и `feedings` создаются строго по SQL-схеме из `spec.md`.
- Для текущей даты создаются только недостающие записи пяти фиксированных слотов; новые слоты первоначально свободны.
- Запись защищена на сервере атомарным обновлением свободного слота или транзакцией. Скрытая кнопка не заменяет эту защиту.
- ФИО для прогулки и кормления проверяется сервером: после обработки лишних пробелов оно должно быть непустым.
- Интерфейс должен позволять пройти главный сценарий на широком и узком экране.

Постоянное состояние нельзя заменять `localStorage`, массивами в памяти процесса, моками или статичной разметкой.

## Локальный запуск

Проверенное окружение: Node.js `24.18.0`, npm `11.16.0`. Проект рассчитан на Node.js 24 версии не ниже `24.18.0`. Внешних зависимостей нет; установка пакетов для запуска не требуется.

В терминале из папки проекта:

```powershell
npm start
```

Откройте <http://127.0.0.1:3000>. Выберите свободное время, введите синтетическое ФИО и нажмите «Записаться». Ниже слотов находится карточка и форма последнего кормления. Сервер доступен только на этом компьютере. Для остановки нажмите `Ctrl+C` в терминале сервера. После изменения файлов перезапустите сервер.

Используется встроенный SQLite-драйвер `node:sqlite`; дополнительная установка не нужна. Файл `boris.sqlite` автоматически создаётся в корне проекта, рядом с `server.js`. В нём находятся таблицы `walk_slots` и `feedings` по схеме `spec.md`. Время записи и кормления сохраняется в UTC, дата прогулок и время в карточке отображаются по Москве.

При запуске и каждом открытии страницы сервер определяет текущую дату в часовом поясе `Europe/Moscow` и создаёт только недостающие слоты этой даты. Повторные запросы сохраняют существующие записи. База и её служебные файлы исключены из Git через `.gitignore`.

Текущие файлы приложения:

- `package.json` — параметры проекта и команда запуска.
- `server.js` — локальный HTTP-сервер на встроенном модуле Node.js.
- `database.js` — схема SQLite, дата по Москве, создание/чтение слотов, атомарная запись и отметки кормления.
- `public/index.html` — шаблон страницы, заполняемый сервером данными из SQLite.
- `boris.sqlite` — локальные данные приложения, создаётся автоматически.

## Данные и границы

Используются только синтетические данные, например «Анна Тестова» и «Илья Примеров». Реальные ФИО, рабочие адреса, секреты, ключи и токены не используются.

В проект не входят авторизация, роли, личный кабинет, администрирование, отмена записи, календарь на неделю, уведомления, история действий, интеграции, масштабирование, второй MVP и production-grade эксплуатация. Второй агент не подключается. Деплой не является частью базового результата.

## Проверка и принятие

Все семь критериев готовности (DoD) и контролируемый smoke-check приведены в `spec.md`; порядок их проверки отражён в `PLAN.md`. Пройденной считается только фактически выполненная проверка с зафиксированным результатом.

Для ручной проверки конфликта откройте страницу в двух вкладках до записи. Займите один свободный слот в первой вкладке, затем отправьте сохранённую форму того же слота во второй: появится отказ, исходное ФИО останется. После обновления страницы запись должна быть видна в обеих вкладках.

Проверочные записи сохраняются в базе. После итогового smoke-check на 06.11.2026 свободен слот `17:00`; остальные слоты этого дня заняты синтетическими сотрудниками. Для новой текущей даты приложение автоматически создаёт пять свободных слотов. Отмены записи и сброса данных в интерфейсе нет.

Работа выполняется по одной явно поставленной задаче за итерацию. После проверки студент принимает изменение и обновляет статус в `PLAN.md`. После последней принятой правки README обновляется до фактического запуска, сценария и границ приложения.
